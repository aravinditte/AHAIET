# API (base http://127.0.0.1:8000)
All errors: {"error":{"code","message","detail"}}.
- GET /api/health -> {status:"ok",service,version,db_ok}
- GET /api/capabilities -> live checks: db_ok, upload limits/formats, preprocessing (pillow, opencv bool, profiles), ocr {tesseract{available,path,traineddata{lang,available,prefix},reason}, kraken{available,reason,version,ketos_cli,checkpoints[]}, scripts[] (the computed support matrix, same as /api/scripts), status}, corpus {status,passages,by_language,words,reason}, morphology {status,reason}, translation {status, verified_reference, per_profile {<profile>: {status, verified_reference, engine, evaluation_state, model_version, engines[]}}, reason}, languages.
- GET /api/scripts -> {scripts:[{id,name,script,route,note,status (supported|unsupported),engine,reason,evaluation{cer,wer,test_set,evaluated_at}|null,checkpoint{id,path,sha256}|null}]}. Support is computed live: hebrew_square follows the Tesseract route; a historical profile is supported only when artifacts/benchmarks/htr-eval-<profile>.json exists with a measured CER whose checkpoint_sha256 matches a Kraken checkpoint file on disk for that profile. Never a stored boolean.
- GET /api/languages -> biblical_hebrew + biblical_aramaic (separate, profile_defined) + 8 future profiles as unsupported/not_available.
- GET /api/models -> the artifacts/manifests/models.json entries, with each translation entry enriched by LIVE artifact state derived from the disk + model card: artifact_state (not_provisioned | provisioned_missing_files | trained_but_not_evaluated | evaluated), ok, missing[] (the exact missing pieces), model_version, artifact_sha256, chrf_pp (only when the evaluation harness recorded one), selection; Kraken entries gain checkpoints_on_disk (path + sha256 of checkpoint files actually present). The manifest alone never proves readiness.
- POST /api/uploads (multipart file) -> {id,format,width,height,size_bytes,sha256}; 400 invalid_image / unsupported_format / upload_too_large / image_too_many_pixels. Validation is by content (Pillow), never extension.
- GET /api/uploads/{id} -> stored image bytes for preview; 404 upload_not_found.
- POST /api/ocr {upload_id, language_profile?, preprocessing_profile? ("conservative"|"enhanced"), psm?, engine? ("auto"|"tesseract"|"kraken"), script_profile?} -> 200 {request_id,status,original_ocr_text,uncertain_spans[{text,conf,line,left,top,width,height}],mean_confidence,word_count,ocr_engine,ocr_lang,ocr_profile,ocr_profile_note,psm,preprocessing{profile,steps},language,processing_time_ms, plus additive script_profile, engine_version, lines (Kraken per-line results), stage_timings_ms} when a real engine exists; 503 ocr_unavailable when no engine is provisioned; 422 empty_transcription when the engine recognises no text; 422 script_unsupported when the engine/script combination is not supported (Tesseract + a historical script, Kraken + a profile the support matrix does not compute as supported — never a silent substitution); 400 unknown_preprocessing_profile / unknown_ocr_engine / unknown_script_profile.
- POST /api/translate {text, source_language?, corrected_source_text?} -> TranslationResponse fields: request_id,status,detected_language,selected_language,script,original_ocr_text,corrected_source_text,english_translation,translation_method,source_references,uncertain_spans,warnings,model_versions,processing_time_ms, plus additive fields populated when a trained local model produced the output: engine ("moses"|"marian"; "verified_reference" for a corpus match), model_version, artifact_sha256, coverage {source_tokens,known_tokens,coverage_ratio,oov_words[]}; plus hybrid-verification fields on every success: verification {overall_status (no_issues_found|warnings|high_risk — never "correct"), checks[{name,status (pass|warn|fail|not_applicable),detail,evidence}], empirical_uncertainty (only measured inputs: OCR mean confidence, retrieval match type, recorded model metrics), note}, provenance {engine, model_id, model_version, artifact_sha256, evaluation_state, dataset_card_sha256, retrieval_citation, cached}, segments[] (passage results), unevaluated_model (true when the producing engine has no harness-recorded metrics), cached (true when served from the translation cache — trained-model outputs only, never verified retrieval), stage_timings_ms. Multiline input (or input over AHAIET_MAX_PASSAGE_CHARS) is processed as a passage: each line is routed independently, status becomes completed|partial|failed (partial = at least one line translated and at least one not; untranslated lines stay empty with per-segment errors in segments[]), and english_translation reassembles the lines in order; limits: AHAIET_MAX_SEGMENTS (default 64) -> 400 too_many_segments, AHAIET_MAX_PASSAGE_CHARS (default 20000) -> 400 passage_too_long. Resolution order: (1) verified corpus match in the selected profile -> 200 with translation_method="verified_reference" and source_references[{passage_id,reference,book,language_profile,match_type (exact|normalized),source_edition,translation_edition,license,provenance,source_text,english_text}] (response shape for this path is unchanged apart from the additive fields, which stay null except engine); (2) the per-profile selected trained engine (selection: an engine with harness-recorded evaluation metrics beats one without; recorded chrF++ from the evaluation harness wins among evaluated engines; no metrics -> Moses before Marian as the documented default) run as a local subprocess — moses (AHAIET_MOSES_CMD) with the shared tokenizer applied, or marian-decoder (AHAIET_MARIAN_DECODER_CMD) with the exported decoder config; out-of-vocabulary source words are listed in warnings and in coverage.oov_words, never silently dropped; 504 translation_timeout when the decoder exceeds AHAIET_TRANSLATION_TIMEOUT_S (default 120s); an artifact that is provisioned but incomplete yields 503 naming the missing pieces; (3) 503 translation_model_unavailable — the detail distinguishes "corpus present but no match" from "no corpus imported", names any provisioned-but-incomplete artifacts, and a variant candidate (match_type="normalized_variant") may be attached as variant_candidate with a warning; a variant is never returned as the translation. 400 empty_text.
- POST /api/retrieval {text, language} -> {match: <source_reference>|null, variant_candidate: <source_reference+warning>|null}. Searches only the given profile's index. 400 unsupported_language / empty_text.
- POST /api/morphology {text, language} -> {language_profile, adapter, words:[{word, status: found|not_found, entries:[{surface,lemma,strongs,morph_code,word_language,reference,source_edition}]}]}. Hebrew and Aramaic adapters read separate word indexes (morphhb H/A-coded words of their own profile's passages). 503 corpus_unavailable when no corpus word index is imported; 400 unsupported_language / empty_text.
- POST /api/process {upload_id, language_profile?, preprocessing_profile?, psm?, engine?, script_profile?} -> creates a jobs row, runs OCR then the passage translation path over the recognised text (the translation stage receives the OCR mean confidence as a measured uncertainty input); the job result stores {ocr, translation, translation_error} and the merged stage timings; {job_id,status,stage,error,stage_timings_ms}. Job status is completed|partial when translation ran (partial mirrors the passage status), done when OCR succeeded but no translation was possible (translation_error records why), failed at stage=ocr when no OCR engine is provisioned, with the reason recorded.
- GET /api/jobs/{id} -> job row; 404 job_not_found. GET /api/jobs/{id}/result -> {job_id,status,stage,error,result,stage_timings_ms}.
- GET /api/history -> {history:[...]} (rows are written by /api/process). DELETE /api/history/{record_id} -> {deleted:id}; 404 history_not_found.

## Remediation contract changes (finding ids in parentheses)

- **POST /api/process is asynchronous (AHAIET-009).** The queued job is persisted and committed before any work runs; the response is **202** `{job_id, status: "queued", stage: "queued", error, stage_timings_ms}`. A bounded background executor drives the finite state machine `queued -> running_ocr -> running_translation -> completed | partial | failed | cancelled`. **POST /api/jobs/{id}/cancel** records a best-effort cooperative cancellation (honoured between stages; a running decoder subprocess is not killed). Jobs carry `expires_at` (AHAIET_JOB_RESULT_TTL_S); expired terminal jobs read back with status `expired`. Jobs left non-terminal by a worker restart are marked `failed` with reason `worker_restarted` at startup. A full queue returns **503** `job_queue_full` with a `Retry-After` header. With `AHAIET_PERSIST_RESULTS=0`, jobs are in-memory ephemeral (same shapes, no SQLite writes).
- **All-segments-failed translation is 422 (AHAIET-011).** POST /api/translate with a passage whose every segment failed returns **422** `translation_failed_all_segments` with the per-segment reasons in `segments[]`. Partial passages stay 200 with status `partial`; a single translated segment stays 200. Inside /api/process, the same condition ends the job in terminal status `failed` (AHAIET-010) — the old non-terminal `awaiting_translation` status no longer exists.
- **Retrieval ambiguity (AHAIET-001/002).** POST /api/retrieval and verified translation now distinguish `text_match` (the text matched a stored key) from `passage_identity_verified` (the match identifies ONE passage). Multiple identities for an exact key, or a diacritic-insensitive key spanning differing vocalized forms, yield **422** `ambiguous_match` from /api/translate with `candidates[]` (reference + editions per candidate) and NO verified translation. TranslationResponse gains additive `text_match`, `passage_identity_verified`, `candidates`, `profile_evidence`.
- **Profile choice (AHAIET-036).** When no profile is selected and the evidence does not single out one profile (matches in multiple profiles, or trained models in multiple profiles), /api/translate returns **422** `profile_choice_required` with `candidate_profiles[]` and `profile_evidence`. A single-profile-evidence request proceeds and states the evidence in `profile_evidence.basis`.
- **Translate lineage (AHAIET-026).** The request accepts `original_ocr_text` (raw, immutable), `corrected_source_text`, `source_language`, and `ocr_request_id` as separate fields. The response echoes them exactly: `original_ocr_text` is the raw OCR text, or **null** when the call has no OCR context (never a copy of the input); `corrected_source_text` is the text actually translated.
- **OCR readiness fields (AHAIET-034).** /api/capabilities `ocr.tesseract` gains `binary_available`, `language_data_available`, `usable`, and `languages` (from a bounded, TTL-cached `tesseract --list-langs` probe). `available` is kept for compatibility.
- **Script tiers (AHAIET-025).** /api/scripts rows gain `tier` (`model_installed` | `experimentally_evaluated` | `production_supported` | `unsupported`) and `evidence` (the production gates). `status` remains: `supported` only for `production_supported`.
- **Capabilities additions.** `retention.last_sweep` (latest maintenance_runs record) and `retention.degraded` (true when a startup sweep failed — AHAIET-017), `persist_results`, and `provisioning_state` (AHAIET-056; see docs/PROVISIONING.md).
- **Access token (AHAIET-045).** When `AHAIET_ACCESS_TOKEN` is set, GET /api/uploads/{id} and GET /api/history require the `X-AHAIET-Access-Token` header (401 `access_token_required` otherwise). Unset = local single-operator mode.
- **Request validation (AHAIET-042).** Profile/engine/preprocessing fields are enum-typed, `psm` is bounded 0..13, text fields have length ceilings aligned with the passage limits, and `upload_id` must be a 64-char lowercase hex string; violations are 422 from schema validation.
- **OCR uncertain spans (AHAIET-028/040).** Each span gains `index` (token occurrence in TSV order), `occurrence_id` (`w<index>`), `block`, `par`, and `line_id`, so highlights address the exact occurrence.

## Re-review contract changes (finding ids NEW-*)

- **Access-token matrix completed (NEW-12).** When `AHAIET_ACCESS_TOKEN` is set, the `X-AHAIET-Access-Token` header is required by every document/result endpoint: GET /api/uploads/{id}, POST /api/process, GET /api/jobs/{id}, GET /api/jobs/{id}/result, POST /api/jobs/{id}/cancel, GET /api/history, DELETE /api/history/{id} — 401 `access_token_required` otherwise. (This supersedes the AHAIET-045 note above, which listed only two endpoints.) The token is never accepted as a query parameter. The frontend stores it only in sessionStorage and fetches the preview image as a Blob through an authenticated request (NEW-11).
- **GET /api/languages derives status live (NEW-18).** Each profile row's `translation_status` is computed from the live corpus + engine state, sharing the capabilities computation: `retrieval_available` (corpus passages exist for the profile), `model_evaluated` (a selected engine with a valid evaluation-run record), `model_installed_unevaluated` (an engine artifact is provisioned but has no valid run record), or `not_provisioned`.
- **Script tiers renamed and tightened (NEW-17).** /api/scripts rows carry `tier` (`engine_installed` | `operational` | `evaluated_on_dataset` | `validated_for_production` | `unsupported`) and `unmet_conditions[]` naming each failed production gate. This supersedes the AHAIET-025 tier names above. `status` remains: `supported` only for `validated_for_production` (Kraken route) and `operational` (Tesseract route).
- **OCR token offsets (NEW-21).** /api/ocr responses gain `tokens[]` ({index, text, char_start, char_end, offset_encoding, line, conf}) and a top-level `offset_encoding` (`unicode_code_points`); each `uncertain_spans[]` entry also carries `char_start`/`char_end` in the same encoding, computed from the engine's assembly order (Tesseract TSV order; Kraken line assembly). Offsets index into `original_ocr_text` by Unicode code point. When an engine cannot provide offsets, spans omit them and the UI labels highlighting approximate.
- **Engine failure categories (NEW-10).** When trained engines exist for the profile but every attempt fails, POST /api/translate returns the categorized failure instead of `translation_model_unavailable`: 504 `translation_timeout` when all attempts timed out (or the most severe failure in a mixed set), 503 with the engine's own code when all were unavailable; the error detail lists each attempted engine and its failure.
- **Selection record (NEW-04/NEW-14).** /api/models translation entries' `selection` block (written by the evaluation harness) carries `selection_basis` (`head_to_head` | `single_evaluated_engine` | `default_order`) and `comparable` (true only for head_to_head). `chrf_pp` is reported only when accompanied by a valid run record (test-set sha256, sample count, metric signature, artifact sha256, date); an unaccompanied score is ignored and flagged `metric_without_run` in the artifact summary.
- **Jobs (NEW-15/NEW-16).** Job rows carry an owning worker id and a heartbeat; startup recovery fails only jobs whose heartbeat is older than AHAIET_JOB_HEARTBEAT_STALE_S (default 120s), with reason `worker_restarted`. OCR inside a job runs in a subprocess bounded by the job deadline (AHAIET_JOB_DEADLINE_S); expiry ends the job `failed` with `ocr_timeout`.
