# Architecture
Monorepo: frontend (Next.js/TS) -> typed client (frontend/src/lib/api.ts) -> FastAPI backend -> modular services -> SQLite + content-hash file storage.
Backend modules: api/routes.py (all /api routes), core/config.py (env-typed Settings), core/errors.py (AppError -> {error:{code,message,detail}}), core/timing.py (StageTimer: per-stage millisecond timings merged into responses and stored on jobs), schemas/models.py (Pydantic contracts incl. TranslationResponse, VerificationReport, passage segments, provenance), services/preprocessing (Pillow content validation, pixel/byte limits, MAX_IMAGE_PIXELS guard; conservative/enhanced OCR preprocessing profiles with step reports), services/ocr (tesseract_adapter via binary resolution + subprocess TSV with word confidences; kraken_adapter: real Kraken integration — detection with version, version-tolerant blla segmentation + rpred recognition over manifest checkpoints, incompatible installs reported not crashed; script_profiles.py + script_profiles.json: the script registry whose support matrix is computed from evaluation records + checkpoint hashes), services/language (profile suggestion; script-alone invariant; passage.py line segmentation/reassembly preserving blank lines; numbers.py + numbers_lexicon.json: documented Hebrew/Aramaic number-word lexicon), services/translation (strict routing: verified corpus reference -> evaluated trained engine -> unevaluated trained engine flagged -> honest unavailable; moses_adapter subprocess, marian_adapter runtime check; passage translation over per-line routing), services/retrieval (per-profile exact/normalized corpus matching with variant candidates; in-process LRU memoisation invalidated by the corpus importer), services/morphology (separate Hebrew/Aramaic adapters over the corpus word index), services/verification (deterministic candidate checks — corpus-evidence coverage, omission/addition risk, named entities, numbers, negation, morphology-backed grammar observations, reference agreement, measured-only empirical uncertainty; statuses never claim correctness), services/language/normalize.py (exact vs diacritic-insensitive search keys), app/corpus/import_morphhb.py (morphhb/WLC + WEB importer), app/evaluation/metrics.py (Levenshtein CER/WER), storage/db.py (sqlite3, MIGRATIONS list + schema_version table; jobs carry stage_timings_json; translation_cache stores trained-model payloads keyed by profile + normalized source + engine + artifact hash — consulted only after verified retrieval misses, hits labelled cached).
Uploads are stored as <sha256><ext-from-detected-format>; user filenames never enter a path. Upload fetch validates the id is 64 hex chars before globbing (traversal-safe).
Models load from artifacts/manifests/models.json; an entry counts only if status=provisioned AND its artifact path exists on disk.
